# 工程协作与独立验收

版本：V0.1。依据：[PRD](../PRD.md)、[架构](architecture.md)、[技术选型](technology.md)、[开发计划](development-plan.md)。本文件规定实施与取证方法，不修改产品需求、真实模型质量门槛或阶段出口。

## 1 交付闭环

每批工作遵循：**需求 ID → 数据与接口合同 → 并行实现 → 独立检查 → 集成验证 → 证据报告**。需求 ID 使用现有 FR、UC、DEV 编号；新增技术任务引用这些编号，不自行扩展产品范围。

| 步骤 | 必须产出 | 退出条件 |
|---|---|---|
| 需求定位 | FR / UC / DEV、输入、输出、确定性规则与待验证假设 | 能说明本批实现什么，以及尚不能证明什么 |
| 合同冻结 | Pydantic 模型、版本、错误语义、示例、文件所有者 | 各实现者可以独立运行，不靠猜测字段衔接 |
| 并行实现 | 分文件实现、必要测试、运行命令、限制 | 完成自己拥有的文件，不覆盖其他任务的改动 |
| 独立检查 | 非实现者检查合同、边界、失败分母和需求一致性 | 问题有具体路径、触发条件、影响与复现方式 |
| 集成验证 | 从同一输入贯穿合同、规则、评测和导出 | 真实执行命令，保留失败；不把局部测试当全流程 |
| 证据报告 | 实际命令、样本分母、产物、结果、未测项和后续条件 | 每条完成声明有对应证据，阶段结论不越界 |

独立检查不只检查计划或实现者自述。检查者读取最终代码，独立运行关键用例，检查实际文件；修复后复验受影响结论。集成负责人对最终工作区状态负责。

## 2 Definition of Ready

开始实现前，任务应具备：

- 明确的需求与阶段编号、输入输出及本批边界。
- 一个合同所有者，明确字段、类型、合法值、空值、目录及评分版本、错误处理。接口改动先通知受影响实现者。
- 约定可执行的正常、空输入、缺失、重复、冲突和失败样例；区分合成样例与真实卷面。
- 明确每位实现者的文件所有权、共享文件所有者和测试入口；共享文件由所有者合入，避免并发覆盖。
- 确认依赖可用性；缺少真实样本、凭据、转换器或字体时，明确该批可完成的离线部分和被阻塞的质量判断。

没有真实样本或模型凭据仍可开始离线基础开发；不能据此宣布 DEV-002 真实模型验证、DEV-004 真实代表题导出或 P0 出口通过。

## 3 当前批次与责任

当前批次为 **P0 离线基础**：数据合同、显式合成样例、模型适配器边界、可复现评测与公式导出原型；提前验证 FR-06、11～13 的组卷硬约束。提前验证不表示已交付 P4，不包含账号、数据库、持久任务、生产权限、网页或真实教学闭环。

| 责任 | 实际模型 / 推理设置 | 文件所有权与工作 |
|---|---|---|
| 总设计与独立验收 | `gpt-6.1-sol` / `high` | 本文件；合同建议、独立代码检查与验收 |
| 集成负责人 | 以实际运行记录为准 | `backend/app/contracts.py`、`curriculum.py`、`practice.py`、包配置与集成 |
| 实现者 A | `gpt-6-luna` / `high` | `backend/app/ai.py`、`evaluation.py`、`evals/fixtures/` 及对应测试 |
| 实现者 B | `gpt-6-luna` / `high` | `backend/app/exporting.py`、`scripts/export_demo.py` 及对应测试 |

工具未提供 `gpt-6.1-luna`，实际使用 `gpt-6-luna`，不得在报告中替换名称。协作模型是开发工具，不能作为平台业务模型识别效果的证据。

后续模型接入批次沿用同一范式：实现者 A 负责 DeepSeek 与共享提取校验，B 负责 Codex CLI 开发验证，集成负责人负责显式选择通路的单题入口及调用方。供应商迁移后分别执行接口测试、伪 CLI 进程测试和导出集成，不把旧批次证据记作新模型实测；当前接入结果见 `acceptance/model-adapters-review.md`。

## 4 共享合同要求

`backend/app/contracts.py` 是本批唯一共享类型来源。以下为合同必须表达的语义；实际字段名以该文件为准，修改时同步调用方与说明。

| 合同 | 必须表达的语义 |
|---|---|
| 内容节点 | 有序文字、LaTeX 公式、图片、小问结构；不得将公式当作可随意丢弃的装饰 |
| 来源区域 | 原资料、页码、区域与坐标约定；跨页题可有多个来源区域 |
| 题目 | 稳定题目 ID、题目版本、同题身份或指纹、完整题干、小问、答案及可选已有解析、处理状态及异常 |
| 标签与难度 | 合法考点、前置知识、目录版本、0～100 分数、等级、规则与模型版本；未知考点拒绝进入可用题库 |
| 组卷配置 | 已学范围、进度版本、目标考点、每考点数量、可选难度配额、原卷排除身份、可复现种子 |
| 练习快照 | 固定题目版本、唯一题目身份、每题单一计数考点、顺序、配置与进度版本、明确缺口 |
| 模型结果 | provider、实际 model、调用/提示或规则版本、原始响应、结构校验结果、尝试和可获得的用量；fixture 明确标记 |
| 评测样本 | 样本 ID、synthetic / real、预期题目及小问、标准关联、原页索引、覆盖类别、可复现输入和运行元数据 |
| 导出结果 | 输入快照 ID、题号映射、题目/答案版、DOCX/PDF 实际路径、转换器/模板版本、公式回退及错误 |

禁止用字段合法或模型自报置信度代替内容正确。题目 ready 由自动完整性与合法性检查决定；缺题干、必要图形或可用答案的题目不能参与组卷。研发核对样本和独立验收不是线上题库人工审核，不引入人工批准状态、审核按钮或必经审核队列。

## 5 Definition of Done

一个实现任务完成须同时满足：

- 合同与 PRD 的对应规则已实现，错误及未支持路径可见，不以占位返回成功。
- 修改限于约定文件；相关文档同步，接口调用方可运行。
- 必要的关键测试真实执行；报告区分已通过、失败、未运行、依赖缺失。测试命令、执行目录及退出状态可复现。
- 独立检查发现的阻塞问题修复并复验；非阻塞限制有准确说明。
- 没有凭据、真实学生卷面或个人信息进入代码和合成样例；原文件路径、外部调用和输出路径经过约束。
- 证据覆盖本批所声称行为；尚未验证的真实模型质量、复杂卷面、打印版面或业务价值明确保留。

“离线基础完成”“真实 P0 通过”“MVP 功能验收通过”“老师认为有价值”是不同结论，后者不能由前者推导。

## 6 独立验收规则

### 6.1 组卷硬约束

必须检查默认每考点 10 题、进阶总数与难度配额一致、同题不重复、多标签题只归属一个目标考点计数、原题排除、ready 与答案可用性。候选所有考点及必要前置知识均属于已学集合；未设置进度拒绝生成，缺题不自动补入超纲题或放宽进阶难度。

至少构造一个“逐考点贪心会假缺题、全局匹配可满足”的重叠样例。缺题时区分各槽位可用候选数与全局容量冲突，不能将独立计数之和当作可同时选入的总数。相同题不同 ID 或版本仍应按同题身份去重；近似扫描重复未实测时明确限制。

### 6.2 评测分母与漏检

评测先固定样本 manifest，再读取预测；不能从预测中生成预期分母。真实样本与合成样本分别统计，不混算效果。至少报告：

| 指标 | 分子 / 分母与必要补充 |
|---|---|
| 完整题目可用率 | 题干、小问、必要图形与答案均正确可用的预期大题数 / 全部预期大题数 |
| 题目覆盖率 | 匹配到至少一个预测的预期题数 / 全部预期题数；另列漏题、重复与额外题 |
| 解析覆盖率 | 可解析或有明确结构结果的样本数 / 全部提交样本数；超时和非法 JSON 留在分母 |
| 已解析关联正确率 | 正确关联数 / 已解析预测关联数；另报全部预期关联数、漏关联和未确定数 |
| 关联召回率 | 正确关联的预期关联数 / 全部预期关联数；防止只返回少数容易项得到高准确率 |

题目/小问/作答关联需以唯一身份或明确匹配规则计数，重复预测不得多次贡献正确数。报告不得出现比例大于 100%；空分母为“不适用”，不能写 100% 通过。未解析、未知标签、未确定、错误、重复及漏检分别保留，不静默剔除；给出各统计项定义，避免将重复类别相加误称总题数。

合成 fixture 只证明计数器、校验器和适配器行为。即使合成样例 100% 通过，也应写“真实识别/关联/难度质量未测”，不能替代开发计划中候选 95% 工程门槛的真实样本验证。

### 6.3 模型适配器

离线默认不发网络请求。真实模式缺凭据、模型或配置时显式拒绝，不回落为 fixture 后伪装真实输出。解析拒绝非法 JSON、缺字段、未知标签及矛盾内容；允许的纠正重试有界并记录。永久错误不无限重试；凭据不进入日志、异常、报告或仓库。上传文本作为数据，不得改变任务指令或触发任意工具执行。

### 6.4 数学导出与安全路径

使用同一快照产生学生/教师 DOCX 及各自 PDF，保持题号与顺序对应，学生版不含答案，教师版保留答案与已有解析。公式或必要图片无法转换时明确失败，或产生可追踪且可见的局部回退；不能输出缺内容的“成功文件”。

验证分式、根式、方程组、上下标、几何配图及跨页大题。DOCX 检查实际文档 XML 中原生数学结构、图片与题号；PDF 检查真实生成文件，逐页渲染核对中文、公式、图形与裁切。只有 DOCX XML 检查不能证明 Word 编辑体验或 PDF 打印布局。转换器/字体缺失时报告阻塞项和已生成产物，不能创建空 PDF 或更名文件充数。

路径必须限制在明确资产根目录及输出目录，拒绝 `..`、越界绝对路径、符号链接逃逸和不受支持的远程 URL。子进程使用参数数组、超时及独立临时目录，不能拼接 shell 命令执行题目内容；Pandoc/LaTeX 原始指令及外部文件读取不得绕过资产限制。LibreOffice 使用任务独立 profile，避免并发冲突。失败不发布半成品，输出文件名不直接信任用户输入。

## 7 集成与证据报告

集成验证先记录工具、依赖和版本，再执行合同及关键规则测试、评测 CLI、导出 CLI。独立步骤可以并行；依赖合同或共享输出的变更顺序执行。新变更只重复受影响验证；失败不得被后续成功输出覆盖。

每批报告至少包含：需求/DEV 编号、最终修改路径、运行环境及命令、退出状态、样本来源与实际分母、合成与真实样本分开结果、产物路径、独立检查及修复、未验证项和下一阶段进入条件。无实际调用时模型名标为“配置候选/未调用”，无价格口径时只报告可获取的用量，不估作实测费用。

本批可接受结论示例：“离线合同及规则通过 N 项测试，合成评测 N 个样本，生成了指定 DOCX/PDF 原型；真实卷面为 0、真实模型调用为 0，因此真实 P0 门槛未验收。”实际数量和产物必须来自最终执行结果，不能复制示例占位。
