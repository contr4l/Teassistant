# 开发计划

版本：V0.1。依据：PRD.md、architecture.md 和 technology.md。

## 1 计划假设与交付原则

按 1 名熟悉全栈开发的工程师、现成托管模型 API、可获取真实试卷样本估算。预计 34～48 个有效工作日，约 7～10 个工作周；这是排期估算，不是已确认的上线日期。账号开通、样本等待和老师反馈等待不计入有效工作日。

先验证识别和数学输出，再扩展业务页面；阶段结束必须交付可运行结果。MVP 不设置人工题库审核。研发样本评测与试用反馈不成为线上每题处理的前置条件。

## 2 阶段安排

| 阶段 | 工期估算 | 主要产物 | 依赖 |
|---|---|---|---|
| P0 技术验证 | 4～6 天 | 样本集、模型评测、试卷关联原型、数学导出样张 | 试卷、答题卡、答案；模型账号 |
| P1 工程与基础数据 | 5～7 天 | 可启动工程、账号权限、文件上传、考点目录、学生及进度 | P0 数据合同与验证结论 |
| P2 自动题库 | 6～8 天 | 自动加工流水线、标签难度、去重、异常重试 | P1 基础设施 |
| P3 学生考试分析 | 6～9 天 | 上传关联、错题分析、原图对照、局部修正、多次汇总 | P1、P0 关联方案；与 P2 共用识别组件 |
| P4 个性化组卷与导出 | 7～10 天 | 默认与进阶组卷、替换、四份导出产物 | P2 可用题库、P3 诊断与进度 |
| P5 老师试用与收敛 | 6～8 天 | 反馈、部署、恢复验证、真实备课试用与问题修复 | P4 完整流程 |

单人按顺序实施，避免同时搭建多个半成品。各阶段包含必要测试；P5 不作为集中补测试阶段。

## 3 P0 技术验证

### DEV-001 收集代表性样本与建立评测基线

- 目标收集 15 套考试资料，每个年级约 5 套，部分包含独立答题卡、跨页题目、几何图、手写过程和部分得分。
- 从中选取至少 100 个完整大题，保留题干、小问、答案、配图和对应作答的核对记录。
- 不足上述数量也可先开始，但报告必须标记实际覆盖，不能声称覆盖全部初中题型。
- 在本地受控目录保存真实材料，代码仓库仅保存脱敏索引或合成测试样例。

验收：每个样本可定位原页；数据可重复用于模型及导出比较；使用目的仅为研发验证。

### DEV-002 验证多模态识别与关联

- 调用实际可用模型，记录页面识别、题目拆分、小问关联、批改信息和答案关联结果。
- 对比标准化页面、整页识别及局部放大重试的效果。
- 测量完整题目可用率、关联正确率、漏题情况、失败可见性、耗时和调用用量。
- 区分批改结果、标准答案比较和 AI 原因推断，不以生成完整 JSON 代替识别正确。

工程目标建议：固定样本中完整题目可用率和已解析作答关联正确率均达到 95%；另列未解析数量及覆盖率，不能通过排除失败项掩盖问题。这是候选工程门槛，不是用户已确认的业务通过标准。

未达目标：先定位图像质量、拆题、模型或坐标关联问题，最多做一轮针对性改进；仍不满足则调整 OCR／模型方案并重估排期，不通过增加题库审核来绕过。

### DEV-003 固定考点与难度数据合同

- 建立首版完整初中考点目录草案与稳定 ID，验证前置关系无环。
- 对样本题执行自动标签和难度评分，准备基础、提高、挑战的锚题。
- 检查是否遗漏影响超纲判定的关联知识，记录 AI 自洽性和重跑差异。
- 明确 JSON Schema、本地校验、模型版本和难度分段。

验收：未知标签不能写入；题库题和学生试题共用评分合同。最终目录需与目标老师实际教学范围核对一次，这不构成逐题审核。

### DEV-004 验证数学导出

- 制作覆盖分式、根式、方程组、上下标、几何配图和跨页大题的样张。
- 验证内容树 → DOCX → PDF，检查中文字体、图形清晰度、题号和答案对应。
- 验证 Word 内文字和可支持公式可编辑。

验收：真实代表题可输出无缺失的题目与答案版本；导出问题清单和回退策略明确。

P0 出口：更新技术选型，确定模型配置、字段合同、样本质量结论和实测成本口径。无法跑通则先解决瓶颈，不直接开发整套后台页面。

## 4 P1 工程与基础数据

| 任务 | 内容 | 验收 |
|---|---|---|
| DEV-101 工程初始化 | React、FastAPI、迁移、锁文件、Compose、环境示例与 CI | 新环境按 README 启动；迁移可重复执行 |
| DEV-102 账号与权限 | 老师及运营角色、会话、对象归属 | 老师 A 无法读取或修改 B 的学生、任务及文件 |
| DEV-103 文件与资料包 | 上传、页序、用途、文件摘要、存储适配器 | 图片和 PDF 可上传与授权查看，失败可重试 |
| DEV-104 考点与学生 | 导入目录、学生 CRUD、章节与考点进度更新 | 进度变更有版本，未知考点不能保存 |
| DEV-105 任务基础 | job、step、outbox、派发器、队列、心跳及恢复 | 杀死 Worker 后恢复；重复投递不重复产生业务记录 |

P1 出口：老师能登录、创建学生、标记进度和上传材料；后台可运行一项可恢复的模拟任务。模拟结果必须明确标记，不伪装为 AI 分析。

## 5 P2 自动题库

| 任务 | 内容 | 验收 |
|---|---|---|
| DEV-201 识别与拆题 | 标准页面、区域坐标、跨页题与小问结构 | 可从结构化题目回到对应原图 |
| DEV-202 答案与标签 | 关联答案、考点与前置知识、难度评分 | 字段合法；模型／规则版本可追溯 |
| DEV-203 去重与版本 | 文件与内容指纹、同题版本关系 | 重传同资料不重复入库；扫描差异问题有评测记录 |
| DEV-204 自动入库 | 完整性检查、ready 与失败状态、分阶段重试 | 成功题自动可检索，无人工审核按钮或必经确认 |
| DEV-205 运营入口 | 资料包上传、处理状态和错误定位 | 可定位到失败页面或题目并重试 |

P2 出口：至少形成一批覆盖三个年级代表考点的可组卷资料；每个试用目标考点按数量和难度统计库存。候选不足通过增加真实资料补齐，不以重复题或生成题填充。

## 6 P3 学生考试分析

| 任务 | 内容 | 验收 |
|---|---|---|
| DEV-301 考试上传 | 考试信息、试题／作答／答案文件分组与补传 | 单卷作答与独立答题卡两种流程均可用 |
| DEV-302 关联与分析 | 题目、小问、作答、批改信息、错误考点 | 原卷可追溯；无证据的扣分及原因不虚构 |
| DEV-303 原图对照 | 关联状态、错题列表、局部修正、未确定提示 | 修改后只重算受影响结果，重跑不覆盖人工修改 |
| DEV-304 多次汇总 | 最近三次默认范围、按考点聚合 | 只有一两次考试也可使用，明确实际覆盖 |

P3 出口：一名学生的三次考试可以得到可追溯的错题考点汇总。老师只处理自己考试中的识别纠正，不维护共享题库。

## 7 P4 个性化组卷与导出

| 任务 | 内容 | 验收 |
|---|---|---|
| DEV-401 候选查询 | 考点、进度闭包、难度、原题排除 | 涉及任一未学知识的题目不进入候选 |
| DEV-402 配额分配 | 默认每考点 10 题、进阶分难度配额、全卷去重 | 数量准确；容量匹配避免贪心误报；实际缺口明确 |
| DEV-403 预览调整 | 替换、删除、顺序、版本快照 | 替换遵守条件，导出题单与预览一致 |
| DEV-404 导出 | 模板、中文字体、DOCX、PDF、题答分离 | 四份产物内容完整、题号相符，支持下载 |
| DEV-405 进度变化 | 检测练习与当前进度差异 | 进度撤回造成超纲时不能静默导出旧题单 |

组卷重点测试：多标签重叠、同题不同来源、题目不足、空候选、难度配额不合法、相同请求重复提交和并发替换。

P4 出口：从资料上传到个性化练习导出的完整流程可演示，并完成 PRD UC-01～08。

## 8 P5 试用与收敛

- DEV-501：接入符合预期、质量评分、节省分钟数和问题原因，关联练习版本，完成 UC-09。
- DEV-502：部署试用环境，验证私有文件访问、备份恢复、Worker 中断、模型超时及导出失败重试。
- DEV-503：邀请约 5 位老师完成真实备课，建议每位先完成至少 2 次任务；这是样本收集目标，不是新增业务通过门槛。
- DEV-504：汇总老师原始评价、符合预期占比、质量分布和自评节省时间；标明老师数、任务数、未反馈数，不将缺失反馈计为满意。
- DEV-505：优先修复错题遗漏、答案错配、超纲、重复题、难度不符及文件缺失；邀请对应老师复测。

P5 出口：以老师是否认为结果基本符合预期作为主要判断，记录不同老师的分歧与未解决问题。未验证通过则进入有针对性的迭代，不擅自设定一个满意度比例宣布通过。

## 9 关键依赖与风险处理

| 依赖或风险 | 最早处理阶段 | 处理方式 |
|---|---|---|
| 代表性试卷、分离答题卡及答案 | P0 | 先收集少量跨题型样本，避免只验证清晰印刷题 |
| 模型账号、地域、配额和费用 | P0 | 进行实际 API 探测；设置单任务用量及尝试上限 |
| 考点完整性与超纲规则 | P0～P1 | 统一目录、前置关系、未学集合；验证多标签题 |
| 难度尺度漂移 | P0、P2 | 锚题、版本化评分；按老师反馈调整后重新评测 |
| 题库规模与目标考点库存 | P2 | 统计各考点／难度可用数；缺题明确反馈 |
| 复杂公式与中文字体 | P0、P4 | 固定字体及转换链，真实文件逐页检查 |
| 重复任务与部分失败 | P1 起 | outbox、幂等写入、阶段持久化、恢复验证 |
| 教师人工修改被重算覆盖 | P3 | 模型输出与人工覆盖分离；保存诊断版本 |

## 10 首个开发批次

下一步从 DEV-001～004 开始，先取得样本与模型调用条件，再搭建验证脚本。若暂缺真实资料或 API 凭据，可先做数据合同、合成样例、组卷规则与导出原型；这些不代替真实识别效果验证。

目前已开始 P0 离线基础实现，协作流程见 `engineering-workflow.md`，实际验收见 `acceptance/`。尚未购买服务、开通账号、部署应用或执行真实模型调用；P0 的真实样本出口仍未验收。模型调用和真实资料处理开始时需使用实际配置，并按项目授权范围执行。
