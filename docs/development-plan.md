# 开发计划

版本：V0.1。依据：PRD.md、architecture.md 和 technology.md。

## 1 计划假设与交付原则

按 1 名熟悉全栈开发的工程师、现成托管模型 API、可获取真实试卷样本估算。预计 34～48 个有效工作日，约 7～10 个工作周；这是排期估算，不是已确认的上线日期。账号开通、样本等待和老师反馈等待不计入有效工作日。

先验证识别和数学输出，再扩展业务页面；阶段结束必须交付可运行结果。MVP 不设置人工题库审核。研发样本评测与试用反馈不成为线上每题处理的前置条件。

|---|---|---|---|
| P0 技术验证 | 4～6 天 | 样本集、模型评测、试卷关联原型、数学导出样张 | 试卷、答题卡、答案；模型账号 |
| P1 工程与基础数据 | 5～7 天 | 可启动工程、账号权限、文件上传、考点目录、学生及进度 | P0 数据合同与验证结论 |

| P3 学生考试分析 | 6～9 天 | 上传关联、错题分析、原图对照、局部修正、多次汇总 | P1、P0 关联方案；与 P2 共用识别组件 |
| P4 个性化组卷与导出 | 7～10 天 | 默认与进阶组卷、替换、四份导出产物 | P2 可用题库、P3 诊断与进度 |

终端范围按 PRD 1.1（2026-11-14 更新）执行：P1／P3 验证同账号下手机上传的材料可在桌面对应学生及考试中查看；P3／P4 的分析修正、组卷预览调整与导出在桌面验收；手机端另验收底部导航切换、返回键、组卷并下载成品 PDF。不增加小程序或原生 App。

## 3 P0 技术验证

### DEV-001 收集代表性样本与建立评测基线

- 目标收集 15 套考试资料，每个年级约 5 套，部分包含独立答题卡、跨页题目、几何图、手写过程和部分得分。
- 从中选取至少 100 个完整大题，保留题干、小问、答案、配图和对应作答的核对记录。
- 不足上述数量也可先开始，但报告必须标记实际覆盖，不能声称覆盖全部初中题型。
- 在本地受控目录保存真实材料，代码仓库仅保存脱敏索引或合成测试样例。

验收：每个样本可定位原页；数据可重复用于模型及导出比较；使用目的仅为研发验证。

### DEV-002 验证多模态识别与关联

- 调用实际可用模型，记录页面识别、题目拆分、小问关联、批改信息和答案关联结果。
- 对比标准化页面、整页识别及局部放大重试的效果。
- 测量完整题目可用率、关联正确率、漏题情况、失败可见性、耗时和调用用量。
- 区分批改结果、标准答案比较和 AI 原因推断，不以生成完整 JSON 代替识别正确。

工程目标建议：固定样本中完整题目可用率和已解析作答关联正确率均达到 95%；另列未解析数量及覆盖率，不能通过排除失败项掩盖问题。这是候选工程门槛，不是用户已确认的业务通过标准。

未达目标：先定位图像质量、拆题、模型或坐标关联问题，最多做一轮针对性改进；仍不满足则调整 OCR／模型方案并重估排期，不通过增加题库审核来绕过。

### DEV-003 固定考点与难度数据合同

- 建立首版完整初中考点目录草案与稳定 ID，验证前置关系无环。
- 对全部结构成功题执行统一考点映射、前置知识与难度评分；来源词条只作证据，不能用已有词条跳过映射，也不因缺词条而跳过 AI。准备基础、提高、挑战的锚题。
- 检查是否遗漏影响超纲判定的关联知识，记录 AI 自洽性和重跑差异。
- 明确 JSON Schema、本地校验、模型版本和难度分段。

验收：未知标签不能写入；题库题和学生试题共用评分合同。最终目录需与目标老师实际教学范围核对一次，这不构成逐题审核。

### DEV-004 验证数学导出

- 制作覆盖分式、根式、方程组、上下标、几何配图和跨页大题的样张。
- 验证内容树 → DOCX → PDF，检查中文字体、图形清晰度、题号和答案对应。
- 验证 Word 内文字和可支持公式可编辑。

验收：真实代表题可输出无缺失的题目与答案版本；导出问题清单和回退策略明确。

P0 出口：更新技术选型，确定模型配置、字段合同、样本质量结论和实测成本口径。无法跑通则先解决瓶颈，不直接开发整套后台页面。

## 5 P2 自动题库

| 任务 | 内容 | 验收 |
|---|---|---|
| DEV-201 识别与拆题 | DOCX 原生提取；PDF/图片适配；题型边界、小问、表格、媒体与显示尺寸；来源层持久化 | 不误收注意事项编号；题号、媒体出现顺序与表格保真；来源可定位，可浏览不等于可组卷 |
| DEV-202 答案与标签 | 按题关联已有答案，解析可选；所有结构成功题统一目录、前置知识及 AI 难度；保留来源词条证据 | 缺答案不能发布；有无词条均走语义加工；未知 ID、占位分数不可写入正式题库；模型／规则版本可追溯 |
| DEV-203 去重与版本 | 文件与内容指纹、同题版本关系 | 重传同资料不重复入库；扫描差异问题有评测记录 |
| DEV-204 自动入库 | 来源到业务内容/定位合同桥接、数学导出适配；发布门禁、等待依赖与分阶段重试 | 表格/公式不丢失，无假坐标；内容、标签、前置知识、难度、版本及去重校验通过才自动 ready；无人工审核按钮 |
| DEV-205 运营入口 | 资料包上传、来源预览、加工进度、等待原因和错误定位 | 来源数、AI 加工数和可组卷数分开展示；可定位到具体题目和失败阶段续跑 |

按[录入工作流 V0.2](question-ingestion-workflow.md)实施：先复用已保存来源，再固定真实目录与合同桥接，完成语义加工真实小样验证，随后处理整批、校验并发布，最后验证组卷与导出。DEV-201 的 DOCX 来源原型已有真实证据，不代表 DEV-202～205 或整个 P2 已完成。

本次来源数据基线为 16 份 DOCX、8 套、200 题，164 题有来源词条、36 题未命中，真实难度评分与正式 ready 均为 0。来源 V2 已实施独立清点、关联状态、公式与段内分割保真、文件副本处理和“答案必需、解析可选”；本批修复范围与证据见 `acceptance/ingestion-hardening-contract.md` 和独立验收记录。后续让全部结构成功题进入同一语义流程，不要求重传原文件；分别报告确认、失败和待核验数，不预先承诺全部发布。

P2 出口：至少形成一批覆盖三个年级代表考点的可组卷资料；每个试用目标考点按数量和难度统计库存。候选不足通过增加真实资料补齐，不以重复题或生成题填充。
