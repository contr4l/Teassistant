## 本批交付口径

本批交付原卷与解析配对、题目拆分、原公式与图形保留、解析来源词条索引、SQLite 持久化及本地浏览产物。结构可用性与正式组卷资格分开：缺少统一目录映射、前置知识和经实际执行的难度评估时，`practice_ready` 保持 false，难度保持 null。不得填默认分数或把解析中的“简单”“难点”等词直接当作 AI 难度实测。

不增加人工题库审核流程。研发的独立核对用于验证导入程序，不是逐题批准后入库的线上环节。自动发现的内容、媒体或配对异常保留到具体记录并明确失败，不能通过省略公式、图形或答案后标为结构可用。

## 入库合同与自动判定

| 合同内容 | 本批必须保留或明确的语义 |
|---|---|
| 来源与配对 | 原卷、解析文件摘要和用途；确定的配对键；文件与题号均唯一；不凭单个题号跨资料匹配 |
| 题目身份 | 配对键、源摘要、题号与处理版本；重复导入稳定，不产生第二批相同记录 |
| 内容顺序 | 原段落范围及原 XML；文字、OLE 预览和 DrawingML 图形按原顺序保留；题干和小问作为完整大题保存 |
| 媒体来源 | 每次引用的位置、relationship ID、原媒体或 OLE 部件、输出资产及存在性；按出现次数核对，不只看独立文件数 |
| 答案与解析 | 原卷题号对应的已有答案、分析与详解；缺失、重号或不明确项有失败原因，不补写答案 |
| 来源词条 | 解析原文中的术语、证据段落/片段和提取规则版本；标为来源索引，不冒充官方统一考点目录或完整前置知识 |
| 状态 | 结构导入/渲染状态及异常独立保存；正式组卷资格另列；未评估难度为 null，不虚构模型或置信度 |
| 持久化与浏览 | SQLite、清单与 HTML 对应同一题目身份；浏览可定位原卷与解析，媒体路径有效 |

具体字段名以本批实现合同为准。已有 `Question.ready` 合同有正式标签及难度约束，本批来源题库不能靠填入虚构值强行满足该合同。

## 独立验收要求

1. 逐文件核对 16 个摘要、8 对配对与正文题号序列；每对 25 题，记录漏题、重号、额外题及未分配的正文段落，不把注意事项当题干。
2. 按每题原卷与解析的段落范围核对 XML、OLE/VML 及 DrawingML 媒体出现次数与顺序；媒体缺失或不支持时自动失败，不能只依据非空文字判成功。
3. 核对答案与题号、来源词条与证据片段，未知标签不自动创建成官方目录；SQLite、导入清单和浏览卡片题目数量一致。
4. 对相同输入再导入，验证题目数和稳定身份不增长；区分重导幂等与尚未验证的跨来源相似题去重。
5. 使用合成反例验证缺配对、重复题号、注意事项编号、段落内拆分文字、外部 relationship、媒体缺失与路径越界；测试中不保存真实试题片段。
6. 对实际浏览产物分层查看选择题公式选项、填空题、长解答题、小问、几何图与解析公式；记录实际查看的题目范围。未逐题视觉核对时不宣称 200 题数学内容全部正确，更不宣称全部页面印刷版式通过。
7. 最终检查 Git 忽略与追踪状态，真实源文档、题目 JSON/SQLite、媒体和浏览内容均只留在本地受控产物目录；保持用户已有其他未提交文档修改。
