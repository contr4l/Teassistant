# 共享题库读取优化：合同与验收

日期：2026-11-14。对应 PRD FR-02～04、FR-11～15，以及管理员共享题库预览、检查、调整和恢复。只优化读取，不改变可用题判定、题库内容、教师数据、模型供应商或 Tools 协议。

## 已确认瓶颈与基线

现有管理员汇总、列表和详情均调用全量加载器，页面先汇总后列表，分页在全量核验之后。使用本机真实 200 题来源库与只读模拟元数据存储，单轮业务函数基线：汇总 3.663 秒、第一页 25 题 3.840 秒、详情 7.358 秒；不含真实数据库和网络，不是 ROCK 5B 实测。

加载器采样中，`Path.read_bytes` 5012 次，其中 Word 400 次、累计逻辑读取约 564.64 MiB；操作系统缓存会影响实际磁盘读取量。性能采样附加开销下加载器为 8.077 秒，不与未采样接口耗时混算。原始性能记录位于忽略目录 `work/bank-read-profile/`。

## 冻结接口与边界

- 原 `load_practice_bank(bank_dir, semantic_dir)` 保持完整核验，不全局改变其调用语义；优化单次加载中相同 Word 文档的重复读取，实际摘要与期望摘要仍逐题比对，并使用相同文档字节检查 ZIP/原生对象。
- 新 `app.bank_cache.load_cached_practice_bank(bank_dir, semantic_dir, *, force=False)` 返回 `PracticeBank`。原异常语义保持，文件或校验失败时不返回旧成功值；`force=True` 强制执行完整核验；提供 `clear_bank_cache()` 供显式清理与测试。
- 进程内有界缓存，键包含规范化题库位置。复用前必须核对全部来源、语义与被引用 run/call 证据的依赖状态；记录路径、设备/文件身份、类型/权限、大小、mtime_ns 与 ctime_ns。目录替换、新增/删除、原地修改（即使恢复 mtime）、同名同大小替换与符号链接改变均应触发重新核验，无法安全建立依赖集合时走完整加载。
- 不以 TTL 接受过期快照，不忽略校验错误。完整加载前后检查依赖是否稳定；遇到变化有界重试后明确失败。并发首次加载合并，避免多请求同时重复扫描同一题库；返回与内部缓存隔离的副本，调用方修改不能污染其他请求。
- 管理员状态每次从现有数据库读取；调整、导入发布和历史恢复不复用旧管理元数据。无调整时不把所有题目再转 JSON 并重建；有调整时仅重新验证被调整题，并保留原全库结构不变量。
- “检查题库”明确强制完整校验。教师库存查询沿用同一缓存加载能力，实际组卷仍执行进度、题数、配额、去重、原题排除和版本检查；导出仍执行源文件/公式/图片检查。
- HTTP 及前端字段保持兼容；Tools 镜像构建输入不变，不增加服务、依赖、人工审核或运行时模型调用。

## 分工

总集成负责管理员/API/库存调用、版本和主动检查、标题摘要读取及文档证据；Luna 实现者 A 负责新缓存模块与失效/并发反例；Luna 实现者 B 负责单次完整加载的 Word I/O 复用和对应反例。独立验收者检查最终实现并独立执行失效、调用方隔离、主动检查、调整与版本切换反例。实际模型使用情况按运行记录填写，不更换名称。

## 验收要求

同一题库冷/热读取分别测量；对比汇总、列表、详情与读取次数、核验调用次数。优先确认结果和阻断原因不变，再报告加速比例。执行有意义的损坏文件、证据修改、mtime 恢复、目录替换、并发与副本污染测试，以及根环境 `make check`。本机性能不能证明板子延迟、并发容量、真实模型质量或教学效果。

## 执行与本机性能结果

实际实现者与独立验收者为 `gpt-6-luna/high`，总集成由当前主会话负责。没有静默改用其他业务模型，也没有调用模型进行这次读取优化。

- 新增进程内最大 4 项 LRU；每次复用前后对所有可枚举依赖进行状态检查，不依赖 TTL。首次并发请求合并；不能安全枚举依赖、存在符号链接时走完整加载，不保存结果；读取期间持续变化最多尝试两次后失败。
- 所有缓存返回值为深拷贝，缓存中的模型不交给调用方。主动检查开始前清除旧项，强制核验失败后不能让下一请求回用旧成功结果。
- 管理员/API 与教师库存均已接入；状态和调整逐次从数据库读取。无调整直接复用验证快照，有调整仅重新验证被修改题；题目身份、顺序和考点目录不变，保留全库不变量。导入发布与历史恢复强制完整核验。
- 缓存命中时不再解析全库标题 JSON；标题摘要按文件身份和修改状态复用，返回独立字典。导入历史的任务查询只针对实际显示的最近 30 条，不再为全部历史记录逐项查询。
- Word 原件的字节和实际摘要仅在单次完整加载内复用，每个引用仍比较各自的期望摘要。原生 ZIP/对象从同一份已验证原件字节读取；ZIP 在异常路径也关闭。原始 `load_practice_bank` 每次显式调用依然完整核验。

同一份真实 200 题自包含包、相同机器，保留原文件、原语义与可用状态。优化前接口业务函数为单轮样本；优化后热读取各测 5 轮取中位数，使用只读模拟管理状态，不含真实 PostgreSQL 或网络。不是统计学基准或 ROCK 5B 延迟承诺。

| 操作 | 原单轮耗时 | 优化后热读取中位数 |
| --- | --- | --- |
| 题库汇总 | 3.663 秒 | 0.4332 秒 |
| 首批 25 题 | 3.840 秒 | 0.4201 秒 |
| 首题详情 | 7.358 秒 | 0.4378 秒 |

优化后冷汇总为 3.6612 秒，首次页面“冷汇总＋后续列表”约 4.08 秒，原两个串行请求约 7.50 秒。首次完整核验仍有成本，没有将冷读和热读混写成全部请求均为 0.4 秒。

单次冷加载 Word `read_bytes` 从 400 次／564.64 MiB 降至 16 次／22.586 MiB（约减少 96% 逻辑字节读取）；完整验证仍读取其余图片和证据。一次冷汇总、预热列表、15 次热读取仅触发 1 次完整加载；热阶段 Word 读取为 0。结果仍为 **200 题、176 可抽取、24 受阻**，没有放宽来源、语义或关联门禁。

复现命令和输出位于忽略目录：`PYTHONPATH=backend .venv/bin/python work/bank-read-performance-v1/benchmark.py`，结果 `benchmark-final.json`；原始基线 `work/bank-read-profile/results.json`。这些文件包含本地性能证据，不作为随镜像分发的题库。
