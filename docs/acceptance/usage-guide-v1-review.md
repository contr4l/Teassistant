## 源码与交互范围

## 独立实际浏览器证据

私有脚本 `work/usage-guide-v1/review_browser.py` 使用现有教师 storage_state，没有读取或保存教师密码。首次 Chromium 在沙箱中因 macOS MachPort 权限退出；正常审批后同一测试入口在隔离浏览器运行成功，不把环境启动失败写成 UI 缺陷。最终证据 `review-v2/result.json`：

- Space、Enter 和点击可以打开；实际 dialog.open 且匹配 :modal，标题关联正确。正反 Tab 各 13 次均留在对话框；内部标题点击不误关闭。
- Escape、关闭按钮、遮罩关闭通过；等待 UI 完成后桌面焦点回帮助入口，body overflow 恢复原值。
- 三个按钮分别真正显示学生档案、考试分析、智能组卷页面。教师本次没有已选学生，空选择保持；没有为了制造非空用例新建用户或学生。
- 390×844、320×568 下，侧栏关闭、面板不超视口且无横向溢出；在正文真实 wheel 后 scrollTop 增长、背景 window.scrollY 不变，证明内部滚动而非整页替代。关闭后焦点返回菜单按钮，overflow 清理通过。已亲看桌面与 320 窄屏滚动后截图。
- 整个教师验证期间业务写请求=[]、page_errors=[]；复用已有会话，没有额外登录 POST。

另独立运行 `review_admin.py`，仅在内存读取既有私有管理员登录文件，不打印或写入密码。登录之后只读导航，实际已有非空学生选择在三次跳转后保持不变，关闭/导航后帮助按钮获得焦点，指南仍只有四个按钮且没有管理员快捷入口。结果 `review-admin/result.json`，业务写请求=[]、page_errors=[]。登录是明确授权的认证操作，不包含资料或设置写入；没有复制管理员凭据或新建业务数据。

凭据处理另作更正：旧私有 Root checker 曾硬编码测试密码，读取旧脚本时意外随工具输出显示过；Root 随后已移除明文登录代码，后续复用私有会话。本文不记录该值，也不声称历史上从未输出过凭据；没有擅自修改用户密码。
