用官方 Google Chrome、新上下文及合成 API 响应检查非 localhost HTTP 上传/修正、处理中考试恢复、分析和组卷完成时的跨学生隔离、取消后在途响应、管理员 A/B 请求乱序及正常重新加载。保留正常完成、失败重试和后台任务继续运行的语义。覆盖手机入口但不冒充真机、真实模型或教师价值验收。

不得提交真实学生材料、凭据、本地截图或原始报告。仅发布源码与验收说明，不自动推送或部署。

## 实施结果

- R-01：新增 `newClientId`，优先 UUID、HTTP 可用时使用随机字节，无 Web Crypto 时才用时间/序号/随机组合；仅用于客户端关联，不是令牌。上传队列与老师修正共用。
- R-02：组卷提交、轮询及取结果绑定学生、挂载状态、任务世代和 AbortController；旧响应/错误/finally 均不发布到新学生。读取历史的慢响应也不能覆盖刚提交的新练习，反馈回包按同一学生世代隔离。
- R-03：合并考试 effect 清理，卸载/切换时终止前端订阅，初始分析读取与最终读取有递增序号；保留另一会话已有的 `refreshExams` 当前学生保护。迟到提交响应不能启动旧订阅。
- R-04：每次进入详情先刷新服务器考试状态，包含同一会话离开前刚创建的任务，再恢复 queued/running 订阅；状态确认及处理期间禁重提。进度查询失败可“重新读取进度”，只重新订阅，不重新提交分析。组卷历史已存在 `job_id`，前端类型显式接收并恢复尚未结束的任务，不新增后端字段。
- R-05：题目选择与详情回包分离，只有当前题目最新请求能更新详情/草稿/加载状态；重复点当前题目不清草稿。保存错误后的 quiet reload 不抢占另一题的请求，保存成功晚回也不覆盖新选择。
- `pollJob` 将取消信号传给实际 fetch；取消后不调用 onUpdate；等待结束或取消时移除监听器，避免长任务累计事件监听。

独立复核找到的“新建分析后切回仍用缓存 job”“组卷历史不续订阅”“保存 A 失败使 B 一直加载”和集成检查发现的“重复点同一题卡加载”均已补齐。未修改后端、数据库或模型供应商；没有重启、推送或部署。
