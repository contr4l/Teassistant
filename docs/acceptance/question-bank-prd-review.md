# 试题库模块 PRD 支持度分析

日期：2026-11-11。依据当前 PRD FR-01～04、UC-01，以及题库向 FR-06、FR-11～15 提供数据的接口要求。本轮为代码、数据和关键反例分析，不修改业务实现、测试源码或真实题库，不执行真实模型调用。

**后续状态：**来源录入正确性第一批已实施为 V2，见[修复执行记录](ingestion-hardening-execution.md)。本文保留修复前的审查事实和当时行号；当前实现及回归证据以新记录为准。业务合同、AI 语义加工、正式发布和真实组卷导出仍待后续实施。

## 1 结论

**现有模块不能完整支持 PRD。当前可交付的是已验证一批 DOCX 的本地来源题库，以及独立的模型、组卷和导出原型；来源题库到可组卷业务题目的链路尚未贯通。**

需要补齐来源处理正确性、版本化业务合同、真实统一目录和 AI 加工、自动发布及候选查询、真实题目的组卷导出，以及平台上传/任务服务。已有来源保存、检索和组卷求解器可继续复用，无须推翻重写。

本轮还在合成反例中发现题答错配、漏题并入上一题、原生 Word 公式静默消失等来源层错误。完成 AI 标记与评分后，这些错误仍会影响组卷，因此应先建立回归并修复来源层，再扩大自动加工。

前批“200 题来源库验收通过”针对给定的 8 套资料；本轮检查 PRD 全部能力及新格式边界。**本轮没有证明当前 200 题发生了所列错配或公式丢失，不能把合成反例写成实际题库错误率。**

## 3 逐项对照 PRD

| 需求 | 已有能力 | 缺口与判定 |
|---|---|---|
| FR-01 批量资料上传、分组及状态 | CLI 扫描 DOCX，保存原件、摘要及结构提示 | **部分。**没有平台上传、显式用途分组、持久阶段任务及续跑；PDF/照片未接入批量题库流程 |
| FR-02 内容结构化与保真 | 本批段落、简单表格、MathType 预览及图形保留，支持来源回溯 | **部分。**结构化小问、可靠分页/区域桥接未完成；其他 Word 数学格式出现静默丢失，题答关联也有反例 |
| FR-02 已有答案及可选解析 | 按特定题号及“【答案】”等标记分块 | **部分且有错误。**题干冲突不校验，解析多题可被吞并；有答案无解析被错误拒绝，同段多标记会误判 |
| FR-03 统一考点与前置知识 | 来源词条证据；单题模型输出 ID 白名单校验；目录闭包工具 | **未贯通。**词条没有映射成真实统一目录 ID，未给本批题目生成合法前置知识；仓库现有目录 fixture 是合成目录 |
| FR-04 AI 难度与评分留痕 | 单题提取合同有 0～100 分，业务合同有难度版本和等级换算 | **未完成真实题库加工。**没有批量评分及发布流程；单题输出缺专用评分依据/锚题信息，构造时沿用默认难度版本，未完成校准与重评分版本管理 |
| FR-02、13 同题去重与版本 | 来源文字/预览字节指纹；组卷算法按多种身份联合去重 | **部分。**没有来源库和考试原题共用的同题身份映射；重复源文件可能让索引失败；指纹不能直接作为可靠语义同题判据 |
| FR-01、UC-01 自动加工、异常追踪与重试 | 构建临时目录、整体原子发布，失败清理；单题问题保存 | **未闭环。**目录构建完成与题库发布不同；没有阶段依赖、续跑及正式 ready 发布。坏文件会回滚本批其他已处理来源 |
| FR-06、11～13 进度、默认 10 题、进阶配额、原题排除及缺口 | 独立 `build_practice` 已实现白名单/前置闭包、配额、全局容量匹配、去重和缺口 | **规则组件可复用，真实库未接入。**没有来源到 Question 的桥接和正式候选查询，也没有学生错题参考难度及原题身份的实际数据链路 |
| FR-14 预览、替换、删除及排序 | 静态页面可搜索、查看题目和展开答案解析 | **部分。**这是来源浏览器，没有练习编辑、替换查询、删除重排或持久快照操作 |
| FR-15 按考点分类、题答分离、Word/PDF | 规范化快照导出组件有考点分组、学生/教师 DOCX 及对应 PDF、进度复检 | **组件可用，真实来源未贯通。**无表格/来源块读取；小公式若直接映射为普通图片会被显著放大；没有本批真实题目的完整导出验收 |
| PRD 第 8 节 平台访问与长任务 | 本地文件保存在被忽略目录，HTML 只读预览 | **平台能力未实现。**没有 HTTP 题库服务、登录授权、私有文件下载及持久任务进度，不应把本地浏览器直接部署为教师产品 |

FR-05 学生档案、FR-07～10 学生考试及诊断、FR-16 反馈属于其他业务模块，不要求题库本身实现。题库应与它们共享目录、题目版本、同题身份、难度及来源接口；完整 PRD 仍依赖这些外部模块。

## 4 本轮实际复现的问题

以下均为**显式合成输入**，没有把真实题目加入源码。诊断脚本退出 0 表示探针执行完成，不能解释成 PRD 功能通过。

| 编号 / 优先级 | 触发与实际结果 | 修复方向及代码定位 |
|---|---|---|
| B01 / 发布前阻断 | 文件名可配对、题号相同，但两份题干完全不同，仍接受另一题答案并标 imported，无异常 | 加题答内容一致性检查，保留冲突；[配对及关联](../../backend/app/docx_ingest.py#L893) |
| B02 / 发布前阻断 | 原卷有 1、3，解析有 1、2、3；解析第 2 题被滤掉，其答案并入第 1 题，仍 imported，无异常 | 两版各自独立清点，再关联，额外题不能被原卷预期集合过滤；[解析切题](../../backend/app/docx_ingest.py#L667) |
| B03 / 发布前阻断 | 原生 OMML 公式存在于源文档，结构化题干 HTML 丢失公式，仍 imported | 识别、保留或明确拒绝不支持的数学节点；本批原件 OMML 为 0，所以前批证据未覆盖；[段落渲染](../../backend/app/docx_ingest.py#L347) |
| B04 / 高 | 两版章节均声明共 3 题，但都仅有 1、3，全部 imported，无缺号警告 | 独立题目清单及编号/声明计数校验；未知总数明确未知，不从结果倒推；[题号选择](../../backend/app/docx_ingest.py#L709) |
| B05 / 高 | 有可用答案、无解析，得到 missing_analysis_text 失败 | 按 PRD 允许解析缺失；[判定](../../backend/app/docx_ingest.py#L940) |
| B06 / 高 | “【答案】…【解析】…”在同一段落，整段被归解析，误报缺答案 | 按段内位置切内容，保留图文顺序；[分块状态](../../backend/app/docx_ingest.py#L782) |
| B07 / 高 | 同一原卷复制改名后具有相同 SHA，生成重复 document ID，实际索引抛 duplicate document id | 区分内容身份与来源记录，重复输入幂等归并；[ID 构造](../../backend/app/docx_ingest.py#L845)、[索引唯一性](../../backend/app/bank_index.py#L173) |
| B08 / 高，桥接时必修 | 将 16×16 合成公式预览按普通 image 节点输出，DOCX 中变为 5.8×5.8 英寸 | 内容合同携带用途与源尺寸，导出限制缩放并保持行内公式；[缩放](../../backend/app/exporting.py#L181) |
| B09 / 高，去重接入时必修 | 2×2 与 1×4 两张表的行优先文字相同，内容指纹相同，被报告为一组重复 | 当前指纹省略表格结构，仅是文字/图像字节范围；正式身份加入结构信息并验证同题规则，不能直接拿此指纹做语义归并；[指纹](../../scripts/build_question_bank.py#L26) |

录入探针还实际记录了：

- 解析文件只有“（解析版）”后缀、没有“精品解析”前缀，会误判为原卷；资料用途缺少显式入口。[用途推定](../../backend/app/docx_ingest.py#L843)
- 没有题型章节时，产生带全局异常但 0 题、0 个题目失败的输出；批次需要明确失败/部分完成语义。
- 答案只有“【答案】”标记时，题目正确被判 missing_answer，但摘要仍统计“有答案 1 题”，统计口径不一致。[摘要](../../scripts/build_question_bank.py#L101)
- 解析内部使用下一题数字编号的步骤，会让正式下一题被误报重号。
- 一份损坏 DOCX 会清理整个构建暂存目录，包括此前成功处理的两份。整体回滚避免发布半成品是正确行为，但目前没有可复用的阶段产物，未实现 PRD 的失败续跑。

当前来源查询没有 ready、状态、难度、版本或教学进度过滤；作为来源查看接口合理，不能直接复用为正式候选接口。[query_bank](../../backend/app/bank_index.py#L355) 单题 AI 工具构造 Question 时默认 ready，当前仅写单题验证 JSON，没有发布到题库；后续接入必须另设完整发布门禁，不能把构造成功当自动发布成功。[AI 转换](../../backend/app/ai.py#L109)

来源指纹与单题识别指纹还使用不同的内容表示；识别器的图形指纹没有纳入图像字节，只保留位置提示。因此原题排除必须建立跨来源和学生卷的共同身份，不能仅把考试题 ID 放入排除列表就假设匹配成功。[识别指纹](../../backend/app/ai.py#L82)

## 5 已有组件如何复用

- 保留 DOCX 来源原件、XML、预览和来源位置的设计，以及 SQLite/JSON/HTML 的研发检索能力。
- 保留已有目录白名单、前置关系闭包和多标签进度检查；补真实目录和来源桥接，不把 48 个来源词条直接当目录。
- 保留容量匹配组卷算法：默认 10、分难度配额、同题容量 1、原题身份组排除和缺口已通过合成规则测试；需要补数据和应用服务。
- 保留规范化快照的考点分组、题答分离、原生公式导出、资产路径约束及原子导出；补表格/公式预览/尺寸桥接及真实文件验收。
- 保留 DeepSeek 业务适配器和显式 Codex CLI 开发验证，增加独立语义加工合同与调用编排，不加入新 Provider 或自动回退。
