# 考点目录 V2 兼容迁移合同

日期：2026-11-11。依据真实首轮输出发现的目录缺口补充 FR-03/04，不改变评分规则、不增加题库人工审核。来源仍为同一 V3 的固定 200 题，输入 manifest、原件及既有 run 均不覆盖。

## 变更与边界

首版 90 点目录没有覆盖一道真实题中的整数整除、公倍数/最小公倍数，以及“恰有一人说错”“谁打碎物品”等真假条件推理。模型明确拒绝套入概率/规律等不相关标签，此为实际目录缺口，不能靠放宽白名单、手写标签或强改成功解决。

新建 `junior-math-2022-draft-v2`，仅增加三个有明确边界的工程点：整数整除/奇偶性与最小公倍数、真假陈述与分类/排除推理、正多边形边长与外接圆半径/边心距。分别属于跨学段基础补充、工程方法粒度和源题暴露的具体专题，均不冒称新增的官方 7～9 年级课标条目。真假点限定真假陈述与唯一说谎者等约束，一般几何分类讨论不一律附加该标签。

原 90 个 ID、名称、前置列表逐字不变；旧子图及旧点闭包完全一致。旧 `is_synthetic=false`、评分版本及来源含义不变。任何旧点改名、删点、改前置或新增点反向影响旧闭包，均拒绝本兼容迁移，需要更完整的语义重评。

## 固定受影响范围

先完成原目录首轮，保留所有失败响应。随后扫描全部 200 题源内容及全部原模型 reasoning/warnings，搜集整除、公倍/公因、最小公倍数、奇偶、余数、真假条件及正多边形与圆等候选，并纳入全部首轮失败题。记录选中原因及未知项；不能只挑空标签题，不能把所有几何分类都当同类缺口。

在 V2 响应前冻结 `affected` manifest：200 总分母、固定全部 ID、原 bank/input/catalog 摘要、受影响 ID 与原因。受影响题必须真实调用 Codex CLI、使用 V2 目录重评；未成功仍保留失败。不得使用研发人员手工填写的标签或分数冒充模型输出。

## 显式迁移与追溯

其余首轮成功题可在新增目录下重新校验白名单、结构、逐标签证据、前置闭包及源摘要后兼容迁移，不声称曾被模型用 V2 重新评估。每行均保存：

- 原 assessment 全字段，不改标签、分数、理由或警告；原 assessment_catalog_version/hash。
- 新 validated_catalog_version/hash，及 migration_method；原题 source_hash。
- 原 run 路径、call 编号、原 request/raw response 文件 SHA、对应响应项摘要、原提示版本、模型/provider/binary 身份。
- 派生闭包单独计算；不得伪造模型逐项前置依据。

迁移程序从原始响应重新校验，与保存的 assessment 对齐后才接受；不能仅相信 sidecar 的成功状态。原失败题不允许兼容迁移；V2 未尝试或失败的受影响题也不能回用 V1 当成功。原始及所有重试记录保持独立，不改写旧 run。

最终仍为 200 个唯一预期 ID，分别报告 V1 兼容迁移数、V2 真实重评数、最终失败数，以及两轮原始成功/失败/未尝试和客户端调用数。不能将“全部题在 V2 白名单下合法”写成“全部题已用 V2 重新模型推理”，也不能将工程合法率写成标签准确率或难度准确率。目录新增点对全部 200 题的语义完备性、教师校准仍未验证。

## 实施与独立验收

- Root：目录 V2 与 provenance、受影响 manifest 冻结、新目录真实调用、合并入口、报告与交付。
- 实现 B：新增 `semantic_migration.py` 与对应合成测试，仅本地合并，不发模型请求、不改旧文件。
- 实现 A：只读缺口调查与受影响候选，私有审计脚本，不改共享目录。
- 独立验收：检查新增点边界、原 90 点及闭包、固定范围、逐行原始响应追溯、版本区分及失败分母，执行反例并报告未知。

总设计与独立验收沿用 `gpt-6.1-sol/high`，实现实际使用 `gpt-6-luna/high`。迁移只是研发层面对语义加工的显式兼容处理，正式业务 ready、教材进度和数学导出仍独立验收。
