# 学生考卷与学情分析 V1 执行记录

本批落实 PRD FR-07～10 的本地开发基础：材料规范化、原题识别、拼页答题卡分区、手写转录、双侧证据关联、批改分值账本、考点信号、局部修正及最近三次独立考试汇总。合同先于实现冻结，见 [合同](exam-analysis-v1-contract.md)、[独立验收](exam-analysis-v1-review.md)；命令见 [使用说明](../exam-analysis.md)。本批没有完成手机上传、老师账号、桌面业务页面或在线异步任务服务。

## 模型与协作

用户明确选择 Codex CLI 进行本轮开发验证。总设计/独立验收实际使用 `gpt-6.1-sol/high`，并行实施实际可用模型为 `gpt-6-luna/high`，已告知其与原计划 6.1 Luna 的差异。真实识别配置模型为 `gpt-6.1-sol`，可执行文件身份、输入图像、Schema、提示、模型响应及失败均保存在忽略目录。服务实际底层模型修订不可独立确认，CLI 未提供 token 用量，不估计费用。

DeepSeek 仍是唯一业务供应商，本批新增的两条显式适配均有离线边界测试；没有真实调用 DeepSeek，也没有自动回退供应商。最初 CLI 在受限进程环境启动失败；经批准使用扩大进程权限后真实调用成功。错误日志与成功记录分开保留，没有用 OCR 或合成文本冒充 LLM 识别。

## 独立分母与真实结果

输入为 9 个材料：8 张原题图和 1 份学生 PDF。10 个物理页中，PDF 第 1 页是同一次考试的 6 张答题卡拼图，第 2 页全白。完整 PDF 按 400dpi 渲染，保留红色矢量批改；原件逐字和图片解码像素由独立验收核对。拼页不增加考试次数，空白页不从物理页分母删除。没有独立标准答案、步骤评分细则、考试日期或教学进度资料。

最终程序结果如下，属于单份材料的开发验证：

| --- | --- | --- |
| 原题大题 | 25/25 | 固定编号 1～25，来自独立原图清点 |
| 大题关联 | 25/25 | 有原题与手写两侧来源，不代表逐字转录正确 |
| 终端任务位置 | 35/37 有转录记录 | 24(3)、25(3) 未关联；不等于原卷未作答或零分 |

## 实跑过程与改进

共保留 27 个不同调用键的记录：布局成功 1、原题成功 8、作答成功 8/失败 4、诊断成功 6。此数包含已弃用的第一轮结果，不等于最终分析输入数，也不代表 CLI 内部 HTTP 重试次数。最终分析复用布局 1 和原题 8，采用第二轮作答 6 与诊断 1；重放没有增加调用键。

第一轮响应识别曾把答题卡印刷内容充作原题证据，另有 Schema 拒绝；失败保留。改为附上对应原题图，要求逐题复用已核验原题来源，并验证阶段、角色、题号、页及区域。第二轮 6 个作答请求全部通过结构与来源门禁。首次集成还发现运行中加载的旧合同与新字段不一致，最终使用冻结后的新进程重放，不重写成功模型结果。

真实 QA 修复包括：完整 PDF 批改保留；整题扣分与局部叉号共存时不误判零分；分裂页眉仅允许同页、同顺序且邻近片段严格拼接为逐题分值原文；根路径前缀仅在可证明时规范化。没有从章节总分均分、倒推总分或硬编码本卷答案。原始模型输出保持原样，修正规则只作用于派生分析。
