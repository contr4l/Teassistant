# 考试分析文件定位修复：合同与验收

日期：2026-11-14；对应 FR-07～10 的分析读取、卷面对照和局部修正。用户报告“读取考试分析失败：file not found”。远程状态尚未读取，不预先认定服务器丢失卷或数据。

## 已定位缺陷

`scripts/analyze_student_exam.py` 将 `intake-with-regions.json` 写入 run 输出目录；`web_jobs._analysis` 却发布 `intake/intake-with-regions.json`，并在重分析恢复人工修正时读取同一错误位置。分析、教师报告可能均存在，GET 分析接口读取错误卷面清单便整体返回 404。现有页面权限测试手工创建正确路径，未覆盖真实任务发布路径。

## 冻结接口

- CLI run 元数据明确给出实际 `intake_path` 和原始图片 `asset_root`，二者是不同目录。后台任务写入真实、已存在且身份匹配的清单路径；新任务在发布前检查，不再成功发布不存在的文件指针。
- 新 `app.exam_artifacts.read_exam_intake(settings, data, *, exam_id, student_id)` 返回 `(ExamIntake, effective_relative_path)`，路径相对私有数据根；失败抛出 `ArtifactUnavailable(ValueError)`。无写操作。
- 清单绑定当前考试、学生及卷面资源根，禁止绝对路径、穿越、反斜杠和符号链接逃逸。仅在原文件确实不存在且路径严格为 `jobs/<id>/<lease>/intake/intake-with-regions.json`、asset_root 严格匹配同一任务的 intake 目录时，兼容读取同一任务的 `run/intake-with-regions.json`。不做全目录搜索，不跨考试猜测，不在原清单存在但损坏/身份错误时回退。
- GET 分析、图片和局部修正共用上述解析；图片仍验证清单中的页 ID 和摘要。所有 API 调用先执行既有 owner 权限校验，错误不泄露服务器绝对路径。
- 运维修复工具默认只读诊断。显式 apply 才更新已确认的旧错误 intake 指针；验证分析与清单考试/学生身份、完整图片及材料摘要、无活动任务、记录 revision CAS。保存私有修复审计，不覆盖分析内容、报告、图片、人工修正或其他字段，不重跑模型。真实缺失分析/数据卷时只报告，不伪造恢复。
- 修复脚本应可在旧应用容器使用，通过同时复制独立 helper 文件加载兼容逻辑；依赖仅现有业务 Python 包，无新供应商、服务、依赖或 Tools 构建变更。
