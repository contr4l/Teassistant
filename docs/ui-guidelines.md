# 教师界面设计约定

版本：V0.1（2026-11-12）。依据：[PRD](../PRD.md)、[网页应用](web-application.md)、[改版提示词](ui-refresh-prompts.md)。本文件约束前端表现层，不新增产品能力，不改 API 与数据结构。第 2 节字号、对比度、圆角与阴影数值已由用户于 2026-11-12 确认采用。

## 1 目标

老师进入页面后能快速找到学生、考试记录和组卷入口；操作中能看清当前状态、缺少的材料和下一步动作。

## 2 规则

1. **业务内容优先**：不放宣传标题、理念说明、欢迎横幅。问候语可保留为一行小字。
2. **一层标题**：每个区域一个标题；不叠加“小标签＋大标题＋说明＋徽章”。说明文字只在删除会损失信息时保留，一句为限。
3. **按内容选布局**：记录用列表或表格；设置用表单分区；卡片仅用于确需独立呈现的内容（如逐题分析）。
4. **颜色**：绿色为识别色与主操作色；其他颜色只表达状态（正确、错误、部分得分、未作答、待核对、失败、处理中）。不用渐变、彩色图标底、装饰图形。
5. **图标**：只用于导航、操作按钮和状态；列表行不默认配图标。不用 Sparkles 等“AI”符号。
6. **可读性（已确认）**：正文 ≥14px，辅助文字 ≥12px，不出现 12px 以下文字；文字对比度 ≥4.5:1（白底）；中文字距 0；中文使用系统无衬线字体。
7. **样式（已确认）**：圆角 6px（控件）/ 8px（面板）；面板不加阴影，仅浮层（弹窗、提示、手机侧栏）有一级阴影；按钮悬停不位移。
8. **步骤**：真实的先后步骤用“1 / 2 / 3”标注在标题前；不加装饰性编号或重复的“第一步”和“01/03”。
9. **主次操作**：每屏一个主按钮；其余为次按钮或文字链接。
10. **实现细节**：教师界面不出现模型名、分析通路、JSON、合同、白名单、事务、版本哈希。仅在开发验证通道启用（`allow_codex`）时显示分析通道选择。管理员界面保留操作所需信息，用管理员能读懂的话描述。
11. **限制必须可见**：识别不确定、待核对、题量不足、处理失败、导出失败等信息保留，并写清原因与处理方式。
12. **数据真实**：只展示现有接口数据，不虚构待办、趋势、准确率、完成率或节省时间。

## 3 文案

- 标题说明“这是什么”；按钮说明“点了做什么”；提示说明“发生了什么、怎么办”。
- 状态写具体：数字＋对象，如“上传中 2/5”“含待核对项”。
- 空状态：现状＋入口按钮，如“暂无考试记录”＋[新建考试]。
- 不用：“让每一……”“真正重要的”“从这里开始”“留出更多时间”“把……放在一起”、自证安全修饰（“安全上传”“授权原图”）、“·”堆叠标签（改用括号）。
- 教学上必要的提示保留：“错误”只代表本次考试的结果，不等于没有掌握。

## 6 公式显示

用户于 2026-11-12 决定在网页中渲染公式（推翻同日较早的“不渲染”决定）。依赖 `katex@0.19.1`（MIT，精确版本，见 `frontend/package.json` 与 `pnpm-lock.yaml`），字体随前端打包，不使用外部 CDN。

- 渲染组件 `frontend/src/MathText.tsx`：识别 `$...$`、`$$...$$`、`\(...\)`、`\[...\]`；`\$` 为普通美元符号；未闭合的分隔符按原文显示。
- 行内公式按 `\displaystyle` 排版，分式与试卷印刷大小一致。
- `trust: false`：`\href`、`\url`、`\includegraphics`、`\html*` 不生成链接或资源，以红色命令名显示。解析失败的公式以红色显示原文，不静默丢弃。
- 使用位置：考试分析的题干、作答转录、分析原因、小问分析、原图标题与证据摘录、教师报告、识别提示；练习卷结构化公式节点。修正弹窗保留源码编辑，并显示实时预览。
- 练习卷 HTML 预览仍使用 MathML 白名单；不支持的公式整体替换为可见提示。

## 7 已知限制（本批不处理）


- 工作台考试列表只能显示当前所选学生的考试，因为现有接口按学生查询考试；界面已明确标注所属学生。
