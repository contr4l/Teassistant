# 界面去模板化改版：提示词顺序

版本：V0.1（2026-11-12）。用途：指导 Teassistant 前端的去模板化、去宣传化改版。本文件是工作方法，不修改 PRD 需求；文中“建议默认值”已由用户于 2026-11-12 确认采用，见 `docs/ui-guidelines.md`。

## 执行顺序

| 步骤 | 目的 | 产出 | 依赖 |
|---|---|---|---|
| 0 诊断 | 摸清现状，不改代码 | 问题清单、基线截图 | — |
| 1 改版合同 | 定方向、规则与边界 | `docs/ui-guidelines.md` | 0 |
| 2 文案 | 统一术语与全站文字 | 对照表 + 术语表 | 1 |
| 3 首页 | 先改问题最集中的页面 | 首页实现 + 四态截图 | 1、2 |
| 4 其余页面 | 登录、学生、考试、组卷、管理 | 各页实现 | 3 |
| 5 全局样式收口 | 清理残留样式 | CSS 精简 | 4 |
| 6 独立验收 | 换视角检查实际页面 | 问题清单 | 5 |
| 7 证据与回归 | 测试、截图入库 | `docs/acceptance/` 记录 | 6 |

步骤 6 由未参与实现的人或 Agent 执行。

## 步骤 0：现状诊断（只读）

```text
请诊断 Teassistant 当前前端界面的模板化、宣传化问题。本步只读，不修改代码。

先读取 PRD.md、docs/engineering-workflow.md、docs/architecture.md 及 frontend/src 全部组件与样式。启动前端，对每个页面截取桌面（1440px）与手机（390px）基线截图。

按以下清单逐项记录“文件:行号 / 页面位置 / 问题 / 影响”：
1. 版式骨架：是否套用“侧栏＋问候＋渐变横幅＋三张指标卡＋最近动态＋快捷入口”的通用模板。
2. 装饰元素：轨道圆环、光晕渐变、CSS 拼贴纸张、星芒符号、假分页（如 01/04）、英文装饰副标、Sparkles 类图标。
3. 图标：每行都配“淡色方块＋图标”的列表；颜色与含义无关的彩色图标底。
4. 层级重复：“小标签＋大标题＋说明＋徽章”叠加；同一信息出现两次（如“第一步”与“01/03”）。
5. 可读性：12px 以下文字、中文负字距、对比度低于 4.5:1 的灰字、过小点击区域。
6. 文案：口号、价值升华、重复句式、自证安全表述、暴露给教师的实现术语。
7. 布局适配：本该用列表/表格的记录被做成卡片；设置项未按表单分区。

输出：问题清单（按严重程度排序）、截图存放路径、需要用户确认的设计取舍。
```

## 步骤 1：总体改版方向与约定

```text
基于步骤 0 诊断，确定 Teassistant 界面改版方向，写入 docs/ui-guidelines.md，作为后续步骤的合同。本步不改业务代码。

范围与边界：
- 围绕已有功能改版，不新增产品能力，不把未确认的设想写成需求。
- 不改 API 调用和数据结构；需改共享接口时先列出所有调用方。
- 保留数学公式、题目配图、原卷对照、识别修正和导出内容的展示能力。
- 保留识别不确定、题量不足、处理失败等必要信息，不为简洁隐藏限制。

设计目标：
老师进入页面后，可以快速找到学生、考试记录和组卷入口；操作过程中能看清当前状态、缺少的材料和下一步动作。

设计规则：
1. 删除宣传标题、理念说明和大面积欢迎横幅，让业务内容靠前。
2. 每个区域保留一个明确标题，不叠加“小标签＋大标题＋说明＋徽章”。
3. 按内容选择布局：记录用列表或表格，设置用表单分区，确需独立呈现的信息再用卡片。
4. 保留现有绿色作为识别色；其他颜色只用于状态（正确/错误/部分/未作答/待核对/失败）；减少渐变、阴影、彩色图标底和装饰。
5. 图标用于识别导航、操作或状态，不为每段文字配图标。
6. 不依赖极小、极淡文字制造层次。已确认数值：正文 ≥14px、辅助 ≥12px、对比度 ≥4.5:1、中文字距 0、圆角 6/8px、阴影最多一级、按钮悬停不上浮。
7. 主操作突出，次操作收敛；真实步骤保留进度提示，装饰性编号删除。
8. 教师界面不暴露实现细节（模型名、分析通路、JSON 合同等）；是否对教师隐藏模型选择需用户确认。

输出：设计约定文档；每个页面的调整方案（问题 → 改法 → 涉及文件）；待确认事项清单。
```

## 步骤 2：全站文案改写

```text
请逐页检查 Teassistant 的界面文案，以熟悉老师工作流程的产品编辑身份改写，遵循 docs/ui-guidelines.md。

写作要求：
- 用老师实际使用的词：学生、考试、试卷、作答、批改、考点、题量、答案、练习卷、导出。
- 标题说明页面或区域是什么（4–8 字为宜）；按钮说明点击后做什么；提示说明发生了什么以及如何处理。
- 状态具体：用数字和对象，如“上传中 2/5”“3 题待核对”。
- 错误 = 发生了什么＋怎么办；空状态 = 现状＋操作入口。
- 说明文字只在删除会损失信息时保留，一句为限。

删除或替换：
- 空泛承诺、情绪铺垫、价值升华：“让每一……”“真正重要的……”“从这里开始”“留出更多时间”。
- 重复句式：“把……放在一起/串在一起”。
- 抽象术语：“学习信号”“考试信号”“分析通路”。
- 自证安全修饰：“安全上传”“授权原图”“由服务端校验”。必要限制在相关位置说明一次。
- “·”堆叠标签：“满分 · 选填”→“满分（选填）”。
- “智能”“个性化”只在有助于理解功能时使用。
- 不为每个标题补副标题，不为每张卡片补口号。

边界：
- 教师界面避免 JSON 合同、事务、白名单等实现术语；管理员界面按操作需要保留，改写为管理员能读懂的话。
- 不改变业务含义，不夸大识别效果，不增加题库人工审核。
- 教学上必要的提示（如“错误”是本次观察、不等同长期未掌握）保留并压缩为一句。

改写示例：
“今天的备课，从这里开始。” → “工作台”
“从需要练习的考点开始” → “选择考点和题量”
“上传一次考试，开始建立学习轨迹。” → “暂无考试记录”＋[新建考试]
“正在安全上传…” → “上传中 2/5”
“选择考试信号” → “参考哪几场考试”

输出：
1. “位置（文件:行号）／原文／改写／原因”对照表；可删除的写“删除”。
2. 全站术语表（同一概念只用一个词），写入 docs/ui-guidelines.md。
```

## 步骤 3：首页专项

```text
按 docs/ui-guidelines.md 与步骤 2 文案表，重新组织工作台首页信息优先级。

内容：
- 优先呈现已有考试记录、对应学生、分析状态及可执行操作；最近考试用紧凑列表或表格（学生／考试／日期／状态）。
- 保留新建考试和常用功能入口，用普通按钮或链接，不配彩色方块图标。
- 删除宣传横幅及星芒、轨道、倾斜纸张等装饰和对应 CSS。
- 问候语可缩小保留，但不占据主要内容区域。
- 重新判断“学生数、考试数、考点目录数”是否需要三张等宽大卡片；低频参考信息降低视觉权重，不为对称保留无用模块。
- 删除指标卡无信息的脚注。

数据边界：
- 只使用现有接口数据。不得虚构待办、趋势、节省时间、准确率或完成率。
- 如展示“需要处理”，只能由现有 analysis_job.status 推导，并在报告中说明来源。
- 没有数据时展示真实空状态与明确入口。

验证：分别检查有记录、无记录、加载中、加载失败四种状态，每种截取桌面（1440px）与手机（390px）截图，说明状态如何构造。
```

## 步骤 4：其余页面专项

```text
按 docs/ui-guidelines.md 与步骤 2 文案表改版以下页面。不改 API 和数据结构；共享组件（Button、Field、EmptyState 等）改动需列出全部使用位置。

【登录页】去掉左侧品牌故事栏、轨道、01/04、TEACHER DESK。改为单栏：产品名＋一句事实性描述＋账号密码表单。保留“账号由管理员创建”。

【学生档案】学生列表保持可扫读；已学考点选择区提高字号、保证点击区域；去掉重复小标签与不变的“档案已保存”徽章。

【考试分析】
- “第一步 · 上传材料”与“01/03”合并为一种真实步骤提示。
- 上传区写清缺少哪类材料（试卷／作答／参考答案）及能否开始分析。
- 题目结果提高正文与辅助字号；状态色只表示作答结果。
- 原卷证据、公式、长题干、修正弹窗完整可读；手机端不截断关键信息。
- 模型选择按步骤 1 确认结果处理。

【组卷】按术语表处理“智能组卷”命名；删除 Sparkles 图标；题量缺口、导出失败等限制保持醒目；练习预览的公式与配图完整。

【管理】保留管理员所需配置和审计信息；实现术语改写为管理员能读懂的说明，如“考点范围、题量、去重、排除原题由系统强制执行，不受提示词影响”。

每页完成后截取桌面与手机截图，覆盖正常、空、加载中、错误状态。
```

## 步骤 5：全局样式收口

```text
清理 frontend/src 样式残留，使其符合 docs/ui-guidelines.md：
1. 删除无引用的装饰类（.story-orbit、.art-*、.welcome-* 等），grep 确认无引用后再删。
2. 散落的硬编码颜色收拢为 CSS 变量：主色、文字、边框、背景、状态色。
3. 统一字号阶梯、圆角与阴影，清除 12px 以下字号与中文负字距。
4. 删除悬停上浮等无意义动效；保留焦点样式，保证键盘可达。
5. 检查对比度，列出仍低于 4.5:1 的位置与修正。
不改变布局结构与功能。完成后运行 make check、make check-web。
```

## 步骤 6：独立验收

```text
请检查 Teassistant 最终实际页面，指出仍存在的模板化设计问题。不参考实现者说明，以浏览器实际截图和操作结果为依据。

逐项检查：
1. 首屏能否直接找到主要操作和最近记录？
2. 是否存在表达同一意思的两层标题或两段说明？
3. 是否还有不说明用途、状态或动作的口号？
4. 是否仍有仅为填充版面的卡片、统计或插图？
5. 字号、对比度和点击区域是否适合日常使用（桌面与手机）？
6. 删除装饰后，导航、操作和状态是否依然清楚？
7. 公式、图片、长题干、原卷证据和错误提示是否完整可读？
8. 是否引入了未实现功能或未经证实的效果承诺？
9. 术语是否与术语表一致？

关键反例必须实际运行：
- 学生与考试列表均为空
- 接口返回错误或超时
- 考试缺少作答材料时点击“开始分析”
- 分析结果为 partial 且有待核对项
- 长题干、复杂公式与配图
- 组卷题量不足
- 390px 宽度下的分析结果与修正弹窗

每个问题给出页面位置、截图、具体影响、最小修改建议。未验证部分明确标注“未验证”及原因。
```

## 步骤 7：证据与回归

```text
整理本次界面改版验收证据，写入 docs/acceptance/ui-refresh-v1.md：
1. 范围：改动的页面与文件；明确未改变的业务行为。
2. 实际使用的模型与分工（如有替代如实记录）。
3. 前后对比截图（桌面＋手机，覆盖步骤 6 关键状态）；截图不含真实学生信息和原始卷面，合成数据显式标记。
4. make check 与 make check-web 结果（命令输出摘要）。
5. 独立验收问题及处理：已修复／暂不处理（附理由）。
6. 结论层级：“界面改版完成”，不等同于“老师价值验证通过”。
同步更新 README 或相关文档中受影响的截图与说明。
```
